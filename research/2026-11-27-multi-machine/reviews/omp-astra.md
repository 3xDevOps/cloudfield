# Adversarial review of draft PR #1186

Review target: `docs/plans/2026-11-27-multi-machine.md` (line numbers below are in that draft). **Verified** identifies source behavior or the proposal's text; **risk** is an inferred failure of the proposed design, not a reproduced incident. No builds, tests or live probes.

## Blocks the design

1. **Silence is not proof of fencing** (plan:32–33, 630–664, 842–846). **Verified:** VMs outlive the agent in independent units (`internal/runtime/vm/unit.go:20–37`). The primary permits replacement after two grace intervals measured at its end, or on an operator assertion. **Risk:** one-way traffic, delayed timer execution, suspend/resume or a primary stall can put the two endpoints on different sides of that deadline. The old VM can still spend tokens or modify external services even if the primary rejects all its messages. **Change:** a link is healthy only after a fresh, two-way application heartbeat. Use an independent fail-closed host watchdog, armed before any VM can run. Do not authorize a *safe* replacement without positive stop/power fencing; distinguish an explicitly unsafe disaster-recovery fork with a new run, branch and revoked old capabilities. Do not claim clocks or silence prove exclusion.

2. **The memory brake can undo the partition fence** (plan:287–293, 649–657). **Verified:** `internal/runtime/vm/freeze.go:43–68` checks the requested freezer flag and can refuse a busy lifecycle lock. `internal/scheduler/vm_freeze.go:118–145` thaws guest holds and the oldest frozen VM after pressure subsides; `internal/runtime/vm/freeze.go:89–98` clears the same bit without checking who owns it. **Risk:** an outstanding hold, an in-progress restore, or pressure subsiding after the disconnection releases a supposedly fenced VM. A successful write is not a kernel acknowledgement that every task stopped. **Change:** one host-side execution gate, with independent link, policy and memory reasons. No start, restore, save path that needs to thaw, or guest hold can bypass a fence. Recover fail-closed on agent restart; have the watchdog confirm the kernel's frozen state or escalate to stopping the VM. Exercise agent death during each transition.

3. **Run ID does not make host mutations idempotent** (plan:312–316, 389–390, 642–648). **Verified:** `internal/runtime/vm/engine.go:227–242` returns *already exists*, not the previous result; it stores the spec fingerprint at lines 285–299. Guest `Boot` promises replay on one helper (`internal/guest/guestpb/guest.proto:10–15`), not across destruction or a different host. **Risk:** the create succeeds and its reply is lost; treating it as a refusal either fails a live launch or starts another copy. A delayed destroy/thaw for an earlier incarnation is more dangerous than a duplicate create. **Change:** commit the machine, run incarnation and intent before any side effect. Name operations by incarnation, operation ID and spec/precondition; persist result or reconcile observed state. Retry an *unknown* outcome only against that incarnation on that host. Only a conclusive pre-create refusal can move an unplaced request.

4. **Rollback can both resurrect and erase work** (plan:635–640). **Verified:** the proposed check is *lower* host-start counter; duplicates are refused only while the first SSH connection is open. The proposed primary restores a backup, then destroys unexpected VMs. **Risk:** restore host image at counter 9 when primary last saw 10: increment to 10 and pass. A clone can reconnect first. Restore yesterday's primary and all today's legitimate sessions look like orphans; previously removed keys may also be valid again. **Change:** quarantine ambiguous inventories; never delete solely because a row is absent. Use primary-issued single-use incarnation credentials outside the host snapshot's rollback history, matched to placement and durable tombstones. Document manual reconciliation/revocation after restoring the authority itself; require fencing the old primary before promoting the backup. Boot counts alone cannot detect rollback of guest data under an unchanged identity.

5. **Remote homes replay writes, not just reads** (plan:556–581). **Verified:** `internal/guest/home/fs_linux.go:30–38,102–119` explicitly allows a call that already ran to run twice; timeout is two minutes, retries three. `internal/guest/home/server_io_linux.go:92–112,138–169,210–230` implements exclusive create, stale handles and true `O_APPEND`. Rename supports `RENAME_EXCHANGE` (`internal/guest/guestpb/home.proto:127–140`). **Risk:** a lost reply can append twice, return `EEXIST` on successful create, or swap two names back. A held request cannot recover the disposition of one the server already executed; a new service can't reopen a renamed/unlinked inode by path. **Change:** specify outcomes per operation. Preserve per-VM/boot handles and bounded operation/result replay across a channel break; across service restart fail uncertain non-repeatable mutations explicitly rather than replaying them. Gate 1c on lost-reply cases and the errors seen by real agents, not just latency.

6. **One token file is not a distributed refresh lock** (plan:547–564, 868–869). **Verified:** `docs/vm-guest.md:237–255` documents stale open files and `flock`/`fcntl` local to one VM. `docs/plans/2026-11-03-shared-account-credentials.md:103–110` describes Codex's use of `flock`; `docs/security.md:242–245` describes token rotation. **Risk:** both VMs can acquire what appears to each to be the same exclusive lock; a refresh in one VM followed by a stale refresh/write from the other can invalidate the real login. The vendor can rotate before a stalled file write reaches the primary. This is not just a cross-IP question; the local-VM limitation already exists. **Change:** require a supported refresh authority/locking and crash-recovery contract per harness, or limit a rotating login to one refresher and document reauthentication on uncertain publication. Make it an acceptance gate, not a throughput experiment. Do not replace vendor refresh with the discarded mechanism by assumption.

7. **Placement permission must follow the data, not just the run's owner** (plan:306–308, 733–739, 772–776). **Verified:** owner, account and home member can differ (`internal/store/runs.go:187–192`); fallback chooses an account, and children inherit extra workspaces (`internal/children/dispatch.go:109–140`). Shared accounts expose another member's login (`docs/security.md:325–332,351–365`); handoff keeps the launcher's account (`internal/scheduler/account_revoke.go:117–123`). Host allowlists are deferred until 1e, after manual launches in 1c. **Risk:** a host allowed for workspace A and its launcher can receive B's secondary repository or a different member's credentials without either owner's approval. **Change:** default to primary-only; intersect *every* workspace and home/account owner's policy before staging anything, including images. Apply to explicit placement, children, fallback, account changes, and reauthorization on reconnect. Ship this boundary with the first remote launch.

## Must fix in the plan

8. **Reconnect is a supervisor transition, not a TCP reconnect** (plan:462–465, 630–634, 812–822, 863–865). **Verified:** helper and git have distinct clients (`internal/runtime/vm/engine.go:146–175`); the home client pings at 10 s with a 5 s timeout (`internal/guest/home/fs_linux.go:49–58`). Git already reopens `Watch` (`internal/gitengine/vm_watch.go:151–191`); an attachment starts at oldest/current, closes on read error and can drop old bytes (`internal/guest/attach.go:26–74`). Scheduler wait treats `ErrNotFound` as exit but transport errors as inconclusive; the VM engine confirms unit/boot locally (`internal/scheduler/supervise.go:28–35,70–86`; `internal/runtime/vm/lifecycle.go:306–338,379–397`). Clock sync runs **after** resume/helper readiness (`internal/runtime/vm/save.go:352–367`). **Risk:** dead channel or stale exit callback can finish a live run; a quiet link can look live; terminal offsets cannot reconstruct missing input or evicted output. A frozen guest cannot answer `SetClock`; a provider can finish and bill a request after its client disappears. **Change:** reconnect by run/boot generation; keep unavailable distinct from absent/exited. Restore policy, reauthorize and admit a controlled thaw, then sync the clock, rebind PTY/ACP/git/coord and report gaps. Include lost stdin, long-running gRPC, hung vs. closed transport, external requests of unknown outcome and suspend/resume in the spike. Don't promise lossless replay.

9. **Mail deduplication does not make wakes, reports or client calls exactly once** (plan:477–506). **Verified:** the 60 s timer is inside the client; timed-out calls need not retry, and sent/unsent/ambiguous failures are distinguished (`internal/coordtransport/client.go:148–159,173–208`; `internal/coordtransport/retry.go:43–69,82–104`). Store deduplication is conditional on a key and the inbox is capped (`internal/store/coord.go:292–319,327–347`). The wake path explicitly expects an unconfirmed turn to wake again in the *same* process and sweeps registered listeners (`internal/coord/acp_wake.go:62–84,180–204`). A report reserves before remote evidence capture; finalize and publication are later (`internal/coord/mailbox.go:644–684,696–724`). **Risk:** the frozen sender cannot retry; the recipient may already have mail, process a prompt twice or never get prompted until its listener returns. A final report can remain pending if the checkout never returns. A long-frozen recipient can also fill its inbox. **Change:** promise a durable *accepted keyed mutation*, not exactly-once execution. Surface unknown/unsent and same-key retry, preserve ack tokens, reconcile pending reports and unread mail on reattach, and specify lost-host resolution without fabricating evidence. Keep duplicate wake prompts harmless.

10. **Reachability is neither delivery state nor wait outcome** (plan:479–485, 508–519). **Verified:** `docs/coordination.md:187–205` distinguishes `last_sent` delivery from lifecycle `recipient_status`. `internal/store/coord.go:538–564` orders by `created_at, rowid`, not insertion alone. Waits expire after seven days and resolve on a published report as well as termination (`docs/coordination.md:1503–1516`; `internal/watch/wait.go:380–415`). An interrupted run yields `resolved: interrupted`, not a failed wait. **Risk:** a delivered but unacked message to a disconnected run loses its meaning in the proposed status; a previously reported outcome remains valid even if the VM is now unreachable. **Change:** expose machine reachability separately, keep current wait/delivery semantics, specify expiry and deduplicate/debounce host notices so flapping cannot fill a parent's inbox.

11. **Neither the snapshot interval nor TCP bounds the loss window** (plan:354–355, 632–637, 666–675). **Verified:** `internal/gitengine/engine.go:60–62` configures snapshot scheduling; `docs/vm-guest.md:649–656` calls a failed or missing Watch a history gap. Branch publication advances a ref only after object fetch and disk checks (`internal/gitengine/vm_watch.go:383–429`); a diff snapshot is not a branch commit. **Risk:** a slow pack, full primary disk or broken Watch makes the latest acknowledged state arbitrarily older than 60 s; relaunching from branch alone omits even acknowledged uncommitted changes. A transcript is not proof a harness can resume its conversation. **Change:** show last verified branch SHA/time, separately recoverable diff/evidence and transcript gaps; define the exact source for a new run and which harnesses can resume. No numerical recovery-point guarantee without a bound on successful durable publication.

12. **A host is an authority for its guests' claims, not an independent witness** (plan:441–452, 688–724). **Verified:** `internal/gitengine/vm_watch.go:383–429` validates objects and binds the branch on the primary, but honors a valid reported HEAD, including a reset; `docs/vm-guest.md:682–695` signs a tree staged by the guest. `internal/signing/agent.go:199–209` signs supplied bytes, not just commits. Coord listeners bind run identity, and children can start real work on an authorized account (`internal/coord/socket.go:380–384`; `internal/children/dispatch.go:109–140`). **Risk:** from a compromised assigned host, valid-looking exits, transcripts, checkouts, reports and child requests are host assertions. A signature or evidence packet can faithfully record a lie; child launches can spend resources elsewhere. **Change:** mark provenance, retain primary validation/quotas, scope signing or explicitly document arbitrary signing while connected, and do not grant additional trust because an outcome is signed, stored, or published. Keep high-authority sessions off untrusted hosts.

13. **The proposed tunnel is broader than the stated grants unless its endpoints change** (plan:221–234, 455–459, 530, 681–702). **Verified:** the pinned ID authenticates the primary (`internal/edge/proto/id.go:15–25`); the existing edge flow also authenticates a claiming account (`docs/edge.md:217–224,235–239`). Existing SSH git authenticates a *member* and exposes workspace `UploadPack` or `ReceivePack`, not a placement-bound base commit (`internal/sshd/session.go:171–201,233–245`). Home isolation is per-server-instance with pre-opened shares and a handle map keyed only by number (`internal/guest/home/server_linux.go:41–79`); forwarded sockets are locally selected trusted paths (`internal/runtime/vm/share.go:39–55,80–110`). **Risk:** a stolen join link enrolls the wrong key; a multiplexed handle, member channel or unrestricted fetch is broader than “base commits only.” **Change:** atomically consume a high-entropy, rate-limited code with proof of key possession; compare host fingerprint out of band before enabling, and avoid bearer secrets in argv/logs. Use a host-only SSH principal with no generic forwarding/member verbs; resolve services, shares, handles and allowed seed objects on the primary per live placement/generation. The primary can push a scoped pack instead of granting repository-wide git access.

14. **Removal is revocation, not erasure; cached policy is not live policy** (plan:530–540, 685–686, 710–746). **Verified:** VM records include environment and secret environment (`internal/runtime/vm/engine.go:285–300`); saved memory and console files are host artifacts (`internal/runtime/vm/record.go:19–42`). Copilot and Antigravity explicitly copy logins at cold start (`docs/harnesses.md:714–732`); the omp broker also serves access tokens and API keys (`docs/security.md:351–365`). Today the egress proxy closes active connections when policy can't be read or stops allowing the host (`internal/egress/proxy.go:321–335`). **Risk:** disconnecting a key neither wipes credentials from images/backups nor closes an existing vendor connection on a compromised host. An honest partitioned host can also enforce a stale allowlist. **Change:** distinguish drain/disable/remove/lost. Revoke all primary grants and active channels on removal; version policy and block stale egress before thaw. Inventory exposed workspaces, owners *including shared accounts*, tokens and keys; document vendor revocation/rotation and disk/snapshot sanitization. Do not claim no logins are copied.

15. **Recovery can deadlock startup or clean up live data** (plan:526–530, 634, 639, 772). **Verified:** `internal/scheduler/recovery.go:689–725,1408–1427,1467–1486` bounds concurrency, interrupts missing sidecars and treats authoritative absence differently from transport failure. Startup waits for recovery and updates can roll back (`docs/failure-handling.md:40`). E1's list explicitly isn't exhaustive; it mixes primary coordination files, host-local disk cleanup and global slot counts (E1:284–309). **Risk:** four unreachable remote probes consume all startup slots, potentially while hosts need the server to accept their links; a blanket host filter leaks primary resources or deletes valid checkouts. **Change:** backfill legacy runs/terminals to the primary; distinguish not-yet-placed requests. Start the control listener and declare local readiness without waiting on an offline host. For each sweep specify authority, scope and `unknown` (defer, never delete); reconcile by bounded per-host inventory with durable pending cleanup. Keep primary-side supervision entries for disconnected runs and process revocations before thaw.

16. **Remote admission needs two-phase authorization and real reservations** (plan:102–106, 270–315, 389). **Verified:** interactive and child launch both hold authorization across `LaunchWithOptions` (`internal/sshd/handlers.go:288–322`; `internal/children/dispatch.go:109–140`). The unlock follows reserve and durable run insertion (`internal/scheduler/launch.go:316–323,399–419`). Capacity is a local gate, counters and a once-only release closure (`internal/scheduler/capacity.go:309–342,373–386`); idle memory may not fit on disk or may still be saving (`internal/scheduler/vm_memory.go:145–184`). **Risk:** one slow host blocks unrelated starts and handoffs. Unlocking without rechecking admits revoked access; lost reserve replies leak capacity and restart forgets claims. Remote free memory also says nothing about the primary's space for incoming packs (`docs/vm-guest.md:689–694`). **Change:** reserve outside global locks with bounded host-issued tokens, expiry for *unused* tokens and atomic consumption by create. Revalidate authorization/policy under lock and commit placement before dispatch; rebuild consumed claims from inventory. Check primary headroom independently; never count reclaimable bytes as free at admit time.

17. **A durable waiting row changes existing launch and restart contracts** (plan:322–340, 389, 753–765). **Verified:** capacity currently precedes run insertion; duplicate reserved IDs return the existing run (`internal/scheduler/launch.go:299–323,399–418`). Queued/provisioning runs enter unstarted recovery; child recovery equates existence of a run row with “started” (`internal/scheduler/recovery.go:720–724`; `internal/children/service.go:189–221`). The dispatcher starts oldest per parent via goroutines (`internal/children/dispatch.go:21–56`), not a global fair queue. **Risk:** restart can interrupt a genuinely waiting run or mark its child started. A permanently ineligible oldest child at a one-slot parent can starve a smaller eligible sibling; repeated kicks can run admission/reclaim across every host while disk is already full. **Change:** separate waiting intent from admitted run, keep idempotent client request ID, policy/base/budget recheck, stable original expiry, and atomic claim/cancel/expire/dispatch. Specify eligible FIFO with per-parent fairness, bounded probes/backoff, hard vs. transient refusal, and distinct unavailable-after-dispatch. Never let retries silently move the base commit or re-spend a slot.

18. **First-use images cannot pass the proposed filter; rollout steps aren't independently usable** (plan:306–315, 530–531, 768–782). **Verified:** the filter requires an image already present; the plan copies a saved environment on first use. An extra checkout needs its own prepared/backing disk (`docs/vm-guest.md:604–616`); guest protocol compatibility is exact, not minimum-based (`internal/guest/client.go:23–26`). **Risk:** a perfectly suitable empty host never becomes eligible. Step 1c promises full sessions before 1d supplies checkouts/network, or before 1e authorizes placement. An updated primary may negotiate the host protocol but refuse the guest of a surviving VM. **Change:** distinguish fetchable from ready; admit space for staging, verify immutable digests/backing chains and clean incomplete transfers. Make a first remote vertical slice include checkout, network, trust and rollback. Define drain/upgrade for incompatible hosts *and guests*, retaining a compatible control path to old VMs or an explicit cold-start decision.

19. **The spike can pass while the design fails under one real workload** (plan:191–192, 242–246, 812–822). **Verified:** commands, VM traffic, terminal, home and packs share one SSH/TCP link; one VM receive may be 4 GiB (`docs/vm-guest.md:689–694`), while terminal reads are sequential 64 KiB (`internal/guest/client.go:30–34`; `internal/guest/attach.go:50–74`). **Risk:** congestion or a primary stall delays heartbeat responses, policy updates and thaws at exactly the moment the full machine needs help. Conversely an SSH keepalive may succeed while the scheduler can't supervise anything. **Change:** measure end-to-end heartbeat age, interactive latency, real git/home throughput, primary CPU/RAM/disk and fairness under concurrent transfer, loss and recovery. Define pass/fail thresholds for the intended LAN before choosing the cut; reserve or isolate control traffic if necessary.

## Worth a sentence

20. **Full host is compared to only one expensive implementation** (plan:174–192, 796–799, 842–846). **Verified:** E7:188–193 estimates RPC counts for a full remote store/controller proxy; E7:195–201 also identifies existing stream-routing seams. **Risk:** counting methods does not establish 3–4× effort or that two machines must write the same session row. Host-local terminal/supervision, durable ordered per-run events and a primary-owned projection can keep recording through a partition without sharing that row. Cross-host coordination, login and revocation still need an explicit offline policy. **Change:** compare that narrower alternative using autonomy during outages, bytes, ownership, recovery and implementation risk; don't wait for outage counts alone to reopen the decision.

21. **No BullMQ is defensible; the stated reason applies to the wrong job** (plan:363–404). **Verified:** E5:30–48 distinguishes older Bull's “double processed” quotation from [BullMQ's stalled job rules](https://docs.bullmq.io/guide/jobs/stalled); a stall can requeue **or fail**, and the evidence found no maximum job duration. **Risk:** a short “reconcile this launch intent” job can run twice without relaunching a VM if finding 3 holds. A SQLite dispatcher needs exactly the same discipline. **Change:** reject an additional stateful dependency because one transactional intent table is sufficient, not because queues inherently duplicate sessions or only suit short jobs. Cite BullMQ for its own behavior.

22. **Two comparative claims overstate their sources** (plan:152–156, 623–627). **Verified:** E4:15 defines [Nomad quorum](https://developer.hashicorp.com/nomad/docs/architecture/cluster/consensus) as a majority: two voters form quorum with both present and tolerate zero failures. E6:191–196 distinguishes [Anthropic's lease expiry](https://code.claude.com/docs/en/self-hosted-environments) at about a minute from reassignment minutes or longer later, with the in-flight turn lost. **Risk:** readers use either claim as justification for timeout-driven failover. **Change:** distinguish quorum from failure tolerance, expiry from reassignment, and conversation continuity from completion of external side effects.
